## 二、Qwen-Audio-3.1-ASR：从「转写」到「理解」

**配图**：`assets/02-ASR模型家族.png`（官方 PPT：Qwen-Audio-3.1 模型家族）

### 2.1 核心发布：五款模型组成「模型家族」

官方 PPT 原话：**「五款模型，按业务场景与音频能力选型」**。

| 模型名称 | 产品定位 | 语音识别 | 分角色转写 | 泛音频理解 | 上下文 | 热词 | 调色 |
|---|---|---|---|---|---|---|---|
| Qwen-Audio-3.1-ASR-Flash-Filetrans | 异步高并发·长音频转写 | ✓ | ✗ | ✗ | ✓ | ✓ | ✗ |
| Qwen-Audio-3.1-ASR-Flash-Streaming | 低延迟流式·语音识别 | ✓ | ✗ | ✗ | ✓ | ✓ | ✗ |
| Qwen-Audio-3.1-ASR-Flash-Message | 输入法场景·语音识别 | ✓ | ✗ | ✗ | ✓ | ✓ | ✓ |
| Qwen-Audio-3.1-ASR-Flash | 语音识别与分角色转写·非流式 | ✓ | ✓ | ✗ | ✓ | ✓ | ✓ |
| Qwen-Audio-3.1-ASR-Next | 统一音频理解大模型·非流式 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

（✓ 支持 / ✗ 不支持，数据来自专场现场 PPT）

### 2.2 三点洞察

**① 用「五款」把场景覆盖做实，而非一个大模型通吃。**
四款 Flash 按调用形态切分（异步批量 / 流式低延迟 / 输入法嵌入式 / 通用+分角色），只有旗舰 ASR-Next 才给「泛音频理解」。这是典型的**产品化分层**：用低成本型号吃量，用旗舰型号吃能力上限。

**② 能力维度从「说了什么」扩到「怎么说的 + 背后是什么」。**
选型表的六列（识别 / 分角色 / 泛音频理解 / 上下文 / 热词 / 调色）里，「泛音频理解」是分水岭——它意味着输入侧不再只取文本语义，还取情绪、环境声、机械声等副语言信息。

**③ 场景外溢：客服、审核、工业三处最直接。**
情绪识别（客服质检）、环境声与违禁声（内容审核）、机械声异常（工业巡检）——原本各需专用小模型，现可由统一音频理解模型承接。

### 2.3 语言与方言覆盖（2026-10-28 官方文档口径）

专场没讲语言数量，但官方文档给了完整清单，`qwen-audio-3.1-asr-flash-message` / `-streaming` / `-filetrans` / `qwen-audio-3.1-asr-flash` 四款完全一致：

| 维度 | 覆盖 |
|---|---|
| 外语 | **29 种**：英、日、韩、越南、泰、印尼、马来、菲律宾、印地、阿拉伯、法、德、西班牙、葡萄牙、俄、意大利、荷兰、瑞典、丹麦、芬兰、挪威、希腊、波兰、捷克、匈牙利、罗马尼亚、保加利亚、克罗地亚、斯洛伐克 |
| 中文方言 | **7 种**：粤语、吴语、闽南语、客家话、赣语、湘语、晋语（+普通话共 8 变体） |
| 官话口音 | **9 类**分区：中原、西南、冀鲁、江淮、兰银、胶辽、东北、北京、港台 |
| 口音落地区域 | **18 个**：河南、陕西、湖北、四川、重庆、云南、贵州、广东、广西、河北、天津、山东、安徽、南京、江苏、杭州、甘肃、宁夏 |

代际对比：Qwen3-ASR（`qwen3-asr-flash*`）为 26 语种、中文 5 变体（普通话 + 四川话、闽南语、吴语、粤语）；更早的 Paraformer v2 是多方言少外语（中文 19 变体、外语 6 种）。

**判断**：这代增量不在外语（3.1 反而裁掉了土耳其语、乌克兰语、冰岛语），而在**中文方言体系化**——从 4 个方言扩到 7 个，并补上「9 类官话口音 + 18 地区」这一层。对国内普通话不标准的真实用户，这比多几种小语种更有价值。

## 三、Qwen-Audio-3.1-TTS：从「真实语音表达」到「全声景生成」

**配图**：`assets/03-TTS架构升级.png`（官方 PPT：Qwen-Audio-TTS 模型架构升级）

### 3.1 迭代谱系（官方 PPT 页）

官方用一页讲「Qwen-Audio-TTS 迭代」，列出四代：

| 代次 | 型号 |
|---|---|
| 第 1 代 | Qwen2-Audio-TTS |
| 第 2 代 | Qwen3-TTS |
| 第 3 代 | Qwen3.5-Audio-TTS |
| 第 4 代 | Qwen-Audio-3.1-TTS-Next |

### 3.2 三点洞察

**① 这是架构级重构，不是参数微调。**
官方单列一页《Qwen-Audio-TTS 模型架构升级》——愿意为「架构」单独开页，通常意味着主干变化（能力上限随之抬升），而非在旧结构上加参数。

**② 生成目标从「人声」扩到「全声景」。**
传统 TTS 的输出是人声朗读；本代的输出是**对白 + 环境声一次性融合**的完整音频。用一句更直白的话：把「配音 → 音效 → 混音」三段工序压成一次生成。

**③ 商业落点明确指向创作型场景。**
官方口径点名有声书、影视剧、播客——这三个场景的共同点是「对白与声场同等重要」，正好是传统 TTS 覆盖不到的部分。

### 3.3 语言与方言（按音色类型分档）

TTS 的语言能力**不能只报一个数**，它按音色类型分三档，选错档位会直接掉能力：

| 音色类型 | 语种 | 中文方言 |
|---|---|---|
| 系统音色（Qwen-Audio-TTS 系） | 因模型与音色而异，以音色列表为准 | 部分音色直出方言，部分靠指令控制 |
| **复刻音色** | **16 种**：中、英、日、韩、俄、法、德、葡、泰、印尼、越、西、意、马来、菲、阿拉伯 | **20 种**：广东、重庆、东北、甘肃、贵州、浙江、河北、河南、湖北、湖南、江西、宁波、宁夏、青岛、陕西、山西、山东、上海、四川、云南（+普通话共 21 变体），通过指令控制设置 |
| 设计音色 | 2 种：中文（普通话）、英文 | 不支持 |
| Qwen-Audio-3.1-TTS-Next | 2 种：中文、英文 | Audiogen 定位（人声+音效+环境音），**非流式** |

对照参考（同期 CosyVoice v3-flash 系统音色）：中文 10 变体（普通话 + 广东、东北、河南、湖南、陕西、山东、四川、安徽、闽南）+ 英日韩印尼。

**判断**：方言能力这代从「只能指令控制」走到「系统音色直出 + 指令控制」并存，但**设计音色与 TTS-Next 都不支持方言**——做方言产品必须锁定「复刻音色」这一条路径。

## 四、Qwen-Audio-3.1-Realtime：全双工与开源实践

**配图**：`assets/04-RealtimeHarness开源.png`（官方 PPT：Realtime Harness 分层架构介绍及开源）

### 4.1 官方议题与开源

议题原名：**「全双工实时语音交互技术与开源实践」**（邓憧）。

官方 PPT 专页《Realtime Harness 分层架构介绍及开源》，并给出开源地址：

```
https://github.com/QwenAudio/qwen-audio-agent
```

### 4.2 三点洞察

**① 范式变化：从「轮流说」到「边听边想边说」。**
全双工意味着系统在播报时仍持续接收、并可对用户的中途发言即时决策——这是语音交互从「对讲机」走向「对话」的分水岭。

**② 关键技术：场景和语义感知的双工控制（官方单列一页）。**
官方 PPT 专设《场景和语义感知的双工控制》，即**不只靠声学 VAD 判停**，而用语义判断「用户是在打断，还是在附和（backchannel）」。这与本项目自研的语义 VAD 路线同构。

**③ 开源策略与 ASR/TTS 不同：开放 Harness，而非开放权重。**
ASR/TTS 走阿里云百炼 API；Realtime 则把**运行时框架（Harness）**开源。判断：越靠近「运行时/框架」的层越倾向开放（便于生态共建），越靠近「模型能力」的层越倾向云服务（保留商业价值）。

### 4.3 双分支架构（技术报告一手证据）

来源：arXiv:2609.25176《Qwen-Audio-3.1-Realtime: Towards Reliable Agentic Voice Interaction》v1（09-21）/ v2（09-24），§2.1 与 Figure 3。

模型内部是**两条同构的 Audio Encoder + LLM 路径 + 一个渲染器**：

| 组件 | 输入 | 输出 | 职责 |
|---|---|---|---|
| 全双工决策分支 | 流式音频 | **继续听 / 开始说 / 停止 / 打断后恢复** 四选一 | 只管时机，不管内容 |
| 语音转文本分支 | 流式音频 | 回复内容（文本） | 只管内容，不管时机 |
| 上下文感知渲染器 | 内容 + 对话历史 + 语音线索 + 声学上下文 | 流式语音 | 由决策信号控制起停 |

报告还明确：`Listen` 与 `Think` 支持 `Act` 与 `Speak` **并发**——工具执行期间可以播报进度。

**判断**：把「什么时候说」与「说什么」在架构层拆成两条分支，说明语义双工控制不是外挂补丁，而是主干设计。这也意味着**自研只需要造决策分支**，不必重造整条链路。

### 4.4 三支柱训练

| 支柱 | 做法 | 解决的问题 |
|---|---|---|
| Think | Core-Cocktail 监督微调 + 多模态/多教师在线策略蒸馏（M²-OPD） | 音频侧缺语言推理能力 |
| Act | 自进化可执行环境 + 多粒度 rollout + GRPO（对话级/里程碑级/轮次级三级奖励） | 工具调用与任务完成 |
| Speak & Coordinate | 对齐「说不说 / 何时说 / 怎么说」，决策策略 π(音频≤t, 历史≤t, 系统状态) | 该沉默时沉默、该等待时等待 |

两条设计原则：① 报告 §5.1 明确「口头承诺既不是执行证据，也不是授权令牌」——权限由运行时强制；② 决策输入含**当前系统状态**（是否在播报、是否在执行工具），动作空间含「打断后恢复」。

### 4.5 端到端 vs 级联：不是取代，是分工

| 维度 | 级联（ASR→LLM→TTS） | 端到端（Realtime S2S） |
|---|---|---|
| 首响应时延 | 三段串联，判停必须等 ASR | 单模型内完成，可边听边判 |
| 打断与抢话 | 依赖外挂 VAD + 规则，易误打断 | 决策分支原生输出「停止/恢复」 |
| 副语言（情绪、语气、笑声） | 文本链路丢失 | 保留，可模仿 |
| sidetalk / 旁人语音 | 靠独立拒识模型，单通道 F1 上限约 0.86 | 3.1 在 FD-Bench v1.5 上把「对背景语音响应率」从 73.0% 压到 13.0% |
| 工具调用 / 长任务 | 天然适配，可回放可审计 | 需外挂 Harness 补 |
| 可调试性 | 每段可埋点、可替换 | 黑盒，只能端到端重训 |

**核心观点（可对外讲）**：一线厂商的**交互入口已全面端到端化**，但「干活」这层反而回到文本 Agent——报告里的持久任务能力来自独立的 Voice Harness 原型（前台 Realtime + 后台文本执行器），报告 §8 自己写明这不是 3.1 模型本身能力、3.1 的端到端评测仍开放。

> 趋势不是端到端取代级联，而是**端到端负责说、级联负责做**。

### 4.6 上架状态与关键参数（2026-10-28）

| 项 | 数值 |
|---|---|
| 正式型号 | `qwen-audio-3.1-realtime-plus`（另有 flash 档） |
| 语种 / 方言 | **14 语种**（3.0 为 11，新增泰、越、阿）+ 中文 21 变体（普通话 + 20 方言） |
| 上下文 | 262,144 / 输入上限 245,760 / 输出 16,384 |
| 价格（元每百万 Token，华北2） | 文本入 5 / 音频入 40 / 文本出 40 / 音频出 150；同时输出文本+音频时只按音频收输出费 |
| 默认音色 | `longanqian_v3.1` |
| 音频对话容量 | 最多 50 轮 / 300 秒 |
| 交互模式 | `server_vad`（声学）、`smart_turn`（声学+语义，附和声不打断）、`push-to-talk`；`smart_turn` 支持**说话人增强**（传预录音频可屏蔽旁人） |

**注意**：`smart_turn` + 说话人增强等于官方把「语义 VAD + 目标说话人锁定」做成了 API 参数——自研语义 VAD 的差异化不能只停在「能判附和声」。

## 六、趋势与启发

### 6.1 三个趋势

**趋势一 · 语音从「转写管道」走向「全双工交互」**
Realtime 的「边听边想边说」+ 官方专列的「场景和语义感知的双工控制」，共同指向：**交互层**不再是 ASR→LLM→TTS 的串行管道，而是持续双向的实时会话。（10-28 修正：这只发生在交互层；执行层仍是文本 Agent，见 4.5）

**趋势二 · 能力分层：识别/合成上云，运行时框架开源**
ASR（五款）与 TTS 经阿里云百炼以 API 提供；Realtime 以 Harness 分层架构开源推进生态。开源与否按「能力的商品化程度」区分。

**趋势三 · 语音模型与硬件深度绑定**
QwenNote A2（随身）、Eva（桌面机器人）、千问 AI 眼镜（穿戴）、钉钉耳机 + 广汽座舱——语音的竞争从「模型指标」转向「入口占有」。

### 6.2 对本项目的五条启发

**① 直接对标物已明确。** Realtime（全双工 + 语义双工控制）可作为自研系统的功能基准，且官方开源 Harness 可对照复现。

**② 语义 VAD 路线被业界确认。** 官方专列「场景和语义感知的双工控制」——不做纯声学 VAD，而用语义判断打断/附和，与本项目路线同构。

**③ 时延指标口径可对齐。** 「说完→开始播」与「模型时延」两套口径业界同在，本项目的双指标定义有外部参照。

**④ 端侧入口是下一战场。** 多类硬件同步承接语音能力——若做产品化，端侧形态（随身/穿戴）优先于纯 Web。

**⑤ 自建只造「决策分支」，不造整条链路。**（10-28 新增）
技术报告的双分支结构说明：差异化集中在「什么时候说、说不说」这一支（1–4B 级即可，数据来自自有对话日志的回合边界/打断点/沉默区间），声学生成能力直接买 API。全自建端到端需要万小时级双工数据与多阶段训练栈，投入产出不成立。

## 附录 B · 回放素材提取方法（可复用）

本洞察使用的现场 PPT 截图并非官方图文稿，而是从官方回放视频逐帧提取，方法如下：

1. 云栖官网回放页（`yunqi.aliyun.com/2026/live`）找到目标专场卡片
2. 点击进入场次页，从页面 `video` 元素取出 HLS（`.m3u8`）地址
3. 用 ffmpeg 按时间点抽帧（须带 `Referer: https://yunqi.aliyun.com/`）：

```bash
ffmpeg -headers "Referer: https://yunqi.aliyun.com/
" -ss 1920 -i "<m3u8-url>" -frames:v 1 -update 1 -y out.png
```

4. 粗扫（每 2-10 分钟一帧）定位章节 → 细扫定位具体 PPT 页 → 裁剪 PPT 区域

**注意**：B 站虽有主论坛回放，但**没有**本专场回放（且反爬严格）；官方回放页才是完整来源。官网 m3u8 为标清（720p），无需登录即可抽帧。
