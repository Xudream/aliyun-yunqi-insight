## 二、Qwen-Audio-3.1-ASR：从「转写」到「理解」

**配图**：`assets/02-ASR模型家族.png`（官方 PPT：Qwen-Audio-3.1 模型家族）

### 2.1 核心发布：五款模型组成「模型家族」

官方 PPT 原话：**「五款模型，按业务场景与音频能力选型」**。

| 模型名称 | 产品定位 | 语音识别 | 分角色转写 | 泛音频理解 | 上下文 | 热词 | 调色 |
|---|---|---|---|---|---|---|---|
| Qwen-Audio-3.1-ASR-Flash-Filetrans | 异步高并发·长音频转写 | ✓ | ✗ | ✗ | ✓ | ✓ | ✗ |
| Qwen-Audio-3.1-ASR-Flash-Streaming | 低延迟流式·语音识别 | ✓ | ✗ | ✗ | ✓ | ✓ | ✗ |
| Qwen-Audio-3.1-ASR-Flash-Message | 输入法场景·语音识别 | ✓ | ✗ | ✗ | ✓ | ✓ | ✓ |
| Qwen-Audio-3.1-ASR-Flash | 语音识别与分角色转写·非流式 | ✓ | ✓ | ✗ | ✓ | ✓ | ✓ |
| Qwen-Audio-3.1-ASR-Next | 统一音频理解大模型·非流式 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |

（✓ 支持 / ✗ 不支持，数据来自专场现场 PPT）

### 2.2 三点洞察

**① 用「五款」把场景覆盖做实，而非一个大模型通吃。**
四款 Flash 按调用形态切分（异步批量 / 流式低延迟 / 输入法嵌入式 / 通用+分角色），只有旗舰 ASR-Next 才给「泛音频理解」。这是典型的**产品化分层**：用低成本型号吃量，用旗舰型号吃能力上限。

**② 能力维度从「说了什么」扩到「怎么说的 + 背后是什么」。**
选型表的六列（识别 / 分角色 / 泛音频理解 / 上下文 / 热词 / 调色）里，「泛音频理解」是分水岭——它意味着输入侧不再只取文本语义，还取情绪、环境声、机械声等副语言信息。

**③ 场景外溢：客服、审核、工业三处最直接。**
情绪识别（客服质检）、环境声与违禁声（内容审核）、机械声异常（工业巡检）——原本各需专用小模型，现可由统一音频理解模型承接。

## 三、Qwen-Audio-3.1-TTS：从「真实语音表达」到「全声景生成」

**配图**：`assets/03-TTS架构升级.png`（官方 PPT：Qwen-Audio-TTS 模型架构升级）

### 3.1 迭代谱系（官方 PPT 页）

官方用一页讲「Qwen-Audio-TTS 迭代」，列出四代：

| 代次 | 型号 |
|---|---|
| 第 1 代 | Qwen2-Audio-TTS |
| 第 2 代 | Qwen3-TTS |
| 第 3 代 | Qwen3.5-Audio-TTS |
| 第 4 代 | Qwen-Audio-3.1-TTS-Next |

### 3.2 三点洞察

**① 这是架构级重构，不是参数微调。**
官方单列一页《Qwen-Audio-TTS 模型架构升级》——愿意为「架构」单独开页，通常意味着主干变化（能力上限随之抬升），而非在旧结构上加参数。

**② 生成目标从「人声」扩到「全声景」。**
传统 TTS 的输出是人声朗读；本代的输出是**对白 + 环境声一次性融合**的完整音频。用一句更直白的话：把「配音 → 音效 → 混音」三段工序压成一次生成。

**③ 商业落点明确指向创作型场景。**
官方口径点名有声书、影视剧、播客——这三个场景的共同点是「对白与声场同等重要」，正好是传统 TTS 覆盖不到的部分。

## 四、Qwen-Audio-3.1-Realtime：全双工与开源实践

**配图**：`assets/04-RealtimeHarness开源.png`（官方 PPT：Realtime Harness 分层架构介绍及开源）

### 4.1 官方议题与开源

议题原名：**「全双工实时语音交互技术与开源实践」**（邓憧）。

官方 PPT 专页《Realtime Harness 分层架构介绍及开源》，并给出开源地址：

```
https://github.com/QwenAudio/qwen-audio-agent
```

### 4.2 三点洞察

**① 范式变化：从「轮流说」到「边听边想边说」。**
全双工意味着系统在播报时仍持续接收、并可对用户的中途发言即时决策——这是语音交互从「对讲机」走向「对话」的分水岭。

**② 关键技术：场景和语义感知的双工控制（官方单列一页）。**
官方 PPT 专设《场景和语义感知的双工控制》，即**不只靠声学 VAD 判停**，而用语义判断「用户是在打断，还是在附和（backchannel）」。这与本项目自研的语义 VAD 路线同构。

**③ 开源策略与 ASR/TTS 不同：开放 Harness，而非开放权重。**
ASR/TTS 走阿里云百炼 API；Realtime 则把**运行时框架（Harness）**开源。判断：越靠近「运行时/框架」的层越倾向开放（便于生态共建），越靠近「模型能力」的层越倾向云服务（保留商业价值）。

## 六、趋势与启发

### 6.1 三个趋势

**趋势一 · 语音从「转写管道」走向「全双工交互」**
Realtime 的「边听边想边说」+ 官方专列的「场景和语义感知的双工控制」，共同指向：语音不再是 ASR→LLM→TTS 的串行管道，而是持续双向的实时会话。

**趋势二 · 能力分层：识别/合成上云，运行时框架开源**
ASR（五款）与 TTS 经阿里云百炼以 API 提供；Realtime 以 Harness 分层架构开源推进生态。开源与否按「能力的商品化程度」区分。

**趋势三 · 语音模型与硬件深度绑定**
QwenNote A2（随身）、Eva（桌面机器人）、千问 AI 眼镜（穿戴）、钉钉耳机 + 广汽座舱——语音的竞争从「模型指标」转向「入口占有」。

### 6.2 对本项目的四条启发

**① 直接对标物已明确。** Realtime（全双工 + 语义双工控制）可作为自研系统的功能基准，且官方开源 Harness 可对照复现。

**② 语义 VAD 路线被业界确认。** 官方专列「场景和语义感知的双工控制」——不做纯声学 VAD，而用语义判断打断/附和，与本项目路线同构。

**③ 时延指标口径可对齐。** 「说完→开始播」与「模型时延」两套口径业界同在，本项目的双指标定义有外部参照。

**④ 端侧入口是下一战场。** 多类硬件同步承接语音能力——若做产品化，端侧形态（随身/穿戴）优先于纯 Web。
